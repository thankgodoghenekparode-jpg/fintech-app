
## Merchant Tools web batch, W-MER-002/003

- `implementation/web/src/invoices/InvoicesPage` and `implementation/web/src/payment_links/PaymentLinksPage` are frontend-only feature pages for host routes `/business/:t/invoices` and `/business/:t/links`; this package does not register host routes or supply authentication, API clients, tenant selection, or wire DTOs.
- Stitch references: `shared_reference/06_stitch-ui-ux/screens/invoices_w_mer_002_1/` and `invoices_w_mer_002_2/`; `payment_links_w_mer_003_1/` and `payment_links_w_mer_003_2/` (each includes screen.png and code.html). Shared web tokens and architecture follow the read-only front-end extracted `DESIGN_TOKENS.json`, `COMPONENT_LIBRARY.md`, `WEB_DASHBOARD_ARCHITECTURE.md`, and `CODING_STANDARDS.md`.
- `InvoiceAdapter` accepts host-mapped presentation rows and a local status filter. The host maps the documented `GET /business/invoices` status/cursor contract. `sendInvoice` exposes only the documented per-invoice send channel (`LINK`, `SMS`, `EMAIL`). The API does not define GET response or create response schemas, and its POST customer/items shapes are open; invoice creation is left to the host and its page action remains unavailable until the host supplies an approved flow. No invoice edit action or bulk reminder is implemented.
- `PaymentLinkAdapter` accepts host-mapped presentation rows and the documented create intent fields (`kind=LINK`, optional amountKobo, description, expiresAt, multiUse). API GET/POST response schemas are unspecified; the host must map values only after those contracts are confirmed. Expiry timezone/boundary remains unresolved. No payment-link deactivation, analytics, use-count inference, share URL, or generated reference is implemented.
- Loading, empty, error/retry, no-match, and action feedback states are in the feature pages. `implementation/web/preview/` is an isolated Vite harness with only local synthetic fixtures, a two-screen selector/sidebar, light/dark toggle, and a persistent non-production notice. It does not make real API/auth/payment/document calls.
- Interaction tests cover listing/filtering, empty/error/retry states, single invoice send channel mapping, and documented payment-link creation field mapping. The API-created link response remains unavailable to both test and preview adapters.
