# Developer 3 Feature Package Specification Gaps

## Merchant Tools

| MER-API-011 | `POST /business/invoices` defines `customer` and each `items` entry as open-ended objects; no field schema or 201 response/invoice identifier is defined. | S-MER-005 uses a frontend-only input model and injected adapter; no wire DTO, response parsing, invoice number, or API client is created. Confirm the mapping before host integration. |
| MER-API-012 | MER-INV-001 requires sending by link, SMS, or email, but the invoice-create body has no delivery channel; the separate send endpoint requires an invoice ID and its response is unspecified. | S-MER-005 passes the selected channel only to its injected UI adapter. Host orchestration remains blocked until create response and delivery sequencing are confirmed. |
| MER-API-013 | `taxBps` is an integer but its allowed range, calculation/rounding semantics, currency representation, and total response are not defined. | S-MER-005 accepts an optional non-negative integer basis-point value and previews entered line values and rate only; it does not calculate tax or invoice totals. Confirm server calculation and validation rules. |
| MER-UI-009 | Customer contact fields, contact validation, and whether contact details are mandatory for each delivery channel are unspecified. Stitch contains customer records and delivery settings not described by the create contract. | S-MER-005 collects a customer name and optional phone/email; it requires the selected phone/email when SMS/email is chosen, with no format or contact storage behavior. Confirm with product/API owners. |
| MER-UI-010 | Stitch create-invoice variants include invoice number/date, payment terms, discounts, settlement account and rails, reminders, statutory/tax claims, save draft/PDF, and calculated totals. These are absent from MER-INV-001's screen spec and/or API schema. | S-MER-005 follows the documented customer/items/tax/due date/notes/preview/send scope and omits these unsupported claims and actions. |
| MER-API-014 | `GET /business/invoices` has no 200 response schema for invoice IDs, customer/reference fields, amounts, statuses, due dates, timeline entries, or pagination cursor. | S-MER-006 uses an injected adapter and UI presentation model; host mapping must use an approved response contract. No response DTO, total, overdue amount, timeline event, or cursor shape is invented. |
| MER-API-015 | The GET `status` query is an unconstrained string; mapping the UI's All/Unpaid/Overdue/Paid categories to the PRD statuses (Draft, Sent, Viewed, Partially paid, Paid, Overdue, Void) is unspecified. | S-MER-006 passes the selected UI filter to the host adapter. The adapter owns the approved query/filter mapping; confirm whether Unpaid includes overdue and partial payments. |
| MER-API-016 | The reminder endpoint accepts LINK/SMS/EMAIL but has no response schema, retry/idempotency guidance, or reminder timeline contract. | S-MER-006 injects reminder delivery. Known rejection is shown as an error; unknown outcome disables another reminder attempt for that invoice during this screen session. Host reconciliation remains unresolved. |
| MER-UI-011 | The S-MER-006 Stitch exports include aggregate collection/outstanding figures, invoice counts, payment rails, copy-link/receipt/PDF, record-cash, statutory reconciliation claims, and sample customer data not covered by MER-INV-002 or the list API response schema. | S-MER-006 omits these fields/actions and displays only adapter-supplied invoice rows, documented statuses, timeline entries, and the documented reminder action. |

| MER-API-007 | `GET /business/payment-requests` has no 200 response schema for identifiers, statuses, amounts, totals, or expiry. | Use an injected adapter and local presentation model only. Rows/totals are absent unless supplied by an approved host mapping. |
| MER-API-008 | `POST /business/payment-requests` has no 201 response schema, including the public reference/share URL needed after create. | Require adapter-provided share text; do not generate or assume URL patterns. |
| MER-UI-006 | Stitch shows custom slugs, customer data requirements, paused/reactivate actions, and transaction/use counts; these are absent from the create/list contracts (which expose `multiUse: boolean`). | Implement only fixed/open amount, description, expiry, and single/multi-use. Omit unsupported link customization and management actions. |
| MER-UI-007 | Expiry timezone and exact boundary semantics are not defined. | The picker submits selected local date/time converted to UTC; confirm this convention with the API owner before integration. |
| MER-API-009 | Payment-request GET/POST responses do not define QR image/payload data, static QR identity, or dynamic QR status/tracking fields; no QR status endpoint is documented. | S-MER-004 uses an injected presentation adapter and status stream. The host must map approved response/push data; this feature does not encode, poll, or fabricate QR content/status. |
| MER-API-010 | The QR standard is named in MER-PAY-002 but no QR encoding payload, certification contract, or render format is provided. | The adapter must supply QR PNG bytes produced by an approved renderer. No QR encoder or external package is introduced in this slice. |
| MER-UI-008 | Stitch S-MER-004 shows NIBSS/CBN certification, settlement claims, merchant/account IDs, audio alert, sample presets, customer note, and print-standee ordering without supporting product/API requirements. | Omit these claims and controls; only documented static/dynamic QR behavior is implemented. |
| MER-INT-002 | The feature host has no shared QR renderer or share/print implementation. | QR image bytes and share/print actions are injected; buttons stay unavailable when host callbacks are absent. |

| MER-API-005 | `POST /business` requires `ownerIdFileKey`, but no owner-document upload/selection contract is documented. | S-MER-002 exposes an injected owner-document selector that must return an opaque key; there is no built-in uploader or invented endpoint. Confirm final copy and restrictions before release. |

## Shared API and runtime

- No production API URL, service credentials, or live response examples are provided. This package does not connect to a production API.
- Only test-local in-memory adapters are used by tests; they are not shipped as production defaults.
- Shared API auth, tenant headers, permission checks, centralized errors, localization, and navigation require Developer 1 integration approval.
