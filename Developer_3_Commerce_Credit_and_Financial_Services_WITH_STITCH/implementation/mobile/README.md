# Merchant Tools Flutter feature package

This is a Flutter library package, not an application. It uses Flutter and Riverpod versions compatible with the existing host constraints (`Dart >=3.4`, `flutter_riverpod ^2.5.1`). It deliberately does not depend on `go_router` because this feature package does not register routes; the host owns route registration.

`MerchantHomePage` implements S-MER-001 using a required `MerchantHomeDataAdapter`, localized copy interface, host token metrics, and action callbacks. `BusinessCreationPage` implements S-MER-002 using a documented-request adapter and an injected owner-document selector. `PaymentLinksPage` implements S-MER-003 using injected list/create adapters and a host share callback. `QrCodesPage` implements S-MER-004 using an injected QR presentation adapter and host share/print callbacks. `InvoiceCreationPage` implements S-MER-005 using a UI-level submission adapter, host copy/tokens, and a host tenant ID; it defines no invoice wire schema or API implementation. `InvoicesPage` implements S-MER-006 using an injected list/reminder adapter. `CashierPage` implements S-MER-007 with injected create/status/share adapters and integer-kobo amount input. `TransactionsPage` implements S-MER-008 with host-mapped balance/transaction data and payout adapter. `RefundPage` implements S-MER-009 with host-mapped refund eligibility and submission adapter. These last three keep auth, response mapping, secure PIN/idempotency, route registration and reconciliation at the host boundary. No production API client, wire response model, authentication, file-upload implementation, QR encoder, or production mock data is included.

From this directory, use `flutter pub get`, `flutter analyze`, and `flutter test` when the Flutter SDK bootstrap issue is resolved. Route registration for `/business`, `/business/new`, `/business/links`, `/business/qr`, `/business/invoices/new`, `/business/invoices`, `/business/cashier`, `/business/transactions`, and `/business/refund/:id` belongs to the shared host. No screen above registers host routes itself.
