Because it is shorter than the 390×844 reference viewport and all other failures in this group also encounter the loading overflow, verify the skeleton on target mobile sizes and make it height-safe. |

## Summary

- S-MER-001 has a real overflow at the test's 800×600 constraints; the other seven S-MER-001 failures share that initial-frame exception. The focused quick-action test sets a 360×800 viewport and passed in the previous suite run, so that result does not establish height safety for the loading skeleton.
- Most remaining failures are attributable to tests querying duplicate text or controls/content that have not been scrolled into the lazy viewport. The cashier-key and S-MER-005 unknown-outcome failures need a focused follow-up to confirm.
- No tests or screens were changed as part of this audit. These failures remain open and should be rerun after targeted test viewport/finder corrections and the S-MER-001 loading-layout review.
