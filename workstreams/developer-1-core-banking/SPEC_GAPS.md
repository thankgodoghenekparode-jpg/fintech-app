# Specification Gaps

These items affect Developer 1 implementation. No undocumented API route, legal version, provider workflow or business limit is assumed.

Card contract v1.1.0 has been drafted locally in the primary OpenAPI file and the frontend is being wired to it. Backend parity and security approval remain outstanding; details and decisions are tracked in [CARD_MODULE_UNBLOCKING_ADDENDUM.md](CARD_MODULE_UNBLOCKING_ADDENDUM.md).

| Area | Gap | Effect |
|---|---|---|
| Legal documents and consent (S-CB-005, S-CB-081) | Both legal-screen handoffs say final Terms and Privacy text will be supplied later; the referenced `back-end/16_legal-templates/` Stage 3 folder is absent. No approved copy, versions, effective dates, fee schedule, data-use disclosure, or consent API appears in the extracted front-end docs or Stitch export. | `/more/legal` follows the S-CB-081 document-list and preferences layout. It opens the actual Terms and Privacy draft files and labels them draft-only; Fee schedule and Data use are explicitly unavailable. Preference switches are disabled and unsaved until approved purposes, document versions and a consent API are supplied. Live onboarding consent remains gated. |
| Branch and agent locator (S-CB-082) | The extracted agent API documents `GET /agents/nearby` query coordinates/radius but no response schema or text-search parameter. Stitch includes sample branches and agents, but no branch endpoint, map provider, or approved location dataset is supplied. | `/locator` includes just-in-time device location, manual area search, verified-agent filtering, radius selection, result details and map directions, using the existing nearby-agent endpoint. `AGENT_LOCATOR_API_UNBLOCKING_ADDENDUM.md` proposes a typed response and `q` query. Backend approval/parity is required. Map tiles and branch listings remain clearly unavailable; Stitch fixture data is not shown as real. |
| Account closure (S-CB-083) | The core API has one-action transaction PIN verification but no closure eligibility, request, or final lifecycle operations. Stitch contains example balances/product counts and a regulatory retention claim that are not backed by approved API or legal sources. | `/more/close-account` reads proposed server-side eligibility, shows exact blockers, requires a reason and one-action PIN token, then submits an idempotent closure request. It never closes the account client-side. `ACCOUNT_CLOSURE_API_UNBLOCKING_ADDENDUM.md` defines the local proposal. Backend, product, compliance and legal approval/parity are required; demo uses a labeled sample blocker and cannot submit. |
| Offline state (S-CB-090) | The Stitch screenshot claims on-device balance/receipt/agent caches, but the app has only short-lived in-memory account/transaction caches and no approved offline receipt vault. | Maintenance state (S-CB-091) | The handoff defines a maintenance message, expected return time and status link but supplies no customer outage schedule, maintenance feed/status endpoint, status URL, or approved emergency contact details. | Session inactivity and re-authentication (S-CB-093) | Security guidance sets a default two-minute idle timeout and lock-on-background, configurable by product/security. A local preview is at `/demo/lock`; it never submits credentials. |
| Account locked or restricted (S-CB-094) | `AUTH_LOCKED` returns a generic 423; `/security/lock` has no typed success state; `/accounts/me` has no restriction reason or permitted-services details; no account-unlock, recovery OTP/selfie, or signed-out support channel is documented. | Login lockout routes to `/account-locked` and displays generic lockout copy plus a sanitized server request ID where present.
